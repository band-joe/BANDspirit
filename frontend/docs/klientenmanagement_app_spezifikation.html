1. Projektübersicht & Ziele

1.1 Vision

Ein zentrales, webbasiertes Klientenmanagement-System für soziale Dienstleister, Beschäftigungsträger und Bildungseinrichtungen. Das System steuert den gesamten Lebenszyklus eines Klienten — vom Erst-Intake über die Einsatzplanung bis zur Abrechnung und Berichterstattung.

1.2 Kernziele

  • MUSS Zentrale Stammdatenverwaltung aller Klienten
  • MUSS Strukturierter Intake-Prozess mit Checklisten
  • MUSS Einsatzplanung mit Kalender-Integration
  • MUSS Vorlagenbasiertes Berichtswesen (PDF/DOCX)
  • MUSS Abrechnungsmodul mit Workflow-Unterstützung
  • SOLL Berufsbilder-Katalog mit Kompetenz-Matching
  • SOLL Arbeitsplatz-Verwaltung mit Kapazitätsübersicht
  • KANN Dashboard mit KPI-Widgets
  • KANN Mobile-responsive Ansichten

1.3 Zielgruppen

RolleBeschreibungHaupt-Module
Fallmanager/inBetreut Klienten, erstellt BerichteStammdaten, Intake, Berichte
Einsatzplaner/inPlant Einsätze und ArbeitsplätzeEinsatzplanung, Arbeitsplatz
Buchhalter/inVerwaltet AbrechnungenAbrechnung, Berichte
TeamleitungÜbersicht, Freigaben, KPIsAlle Module (Read/Approve)
AdministratorSystemkonfiguration, BenutzerverwaltungAdmin-Panel

7.4 Geschäftsregeln

  • Ein Klient kann max. 1 aktiven Einsatz gleichzeitig haben
  • Der Arbeitsplatz darf nicht überbucht werden (belegte_plaetze < kapazitaet)
  • Einsätze können nur für Klienten mit Status AKTIV und abgeschlossenem Intake erstellt werden
  • Bei Statuswechsel → BEENDET wird automatisch ein Abschlussbericht angefordert

11. Workflow-Engine

11.1 State-Machine-Konzept

Die Workflow-Engine basiert auf einer generischen State-Machine, die für verschiedene Module konfiguriert werden kann.

// Workflow-Definition (Konfigurierbar pro Modul) interface WorkflowDefinition { name: string; // z.B. "abrechnung_freigabe" states: WorkflowState[]; // Alle möglichen Zustände transitions: Transition[]; // Erlaubte Übergänge initialState: string; finalStates: string[]; } interface Transition { from: string; // Ausgangszustand to: string; // Zielzustand action: string; // z.B. "einreichen", "genehmigen" requiredRole: Role[]; // Wer darf die Aktion ausführen requiredFields?: string[]; // Pflichtfelder (z.B. Ablehnungsgrund) hooks?: { before?: (ctx) => Promise; // Vor-Prüfung (Validierung) after?: (ctx) => Promise; // Nach-Aktion (Benachrichtigung, Log) }; } // Beispiel: Abrechnungs-Workflow const abrechnungWorkflow: WorkflowDefinition = { name: "abrechnung_freigabe", states: ["ERSTELLT","EINGEREICHT","GEPRUEFT","GENEHMIGT","ABGELEHNT","EXPORTIERT"], initialState: "ERSTELLT", finalStates: ["EXPORTIERT", "STORNIERT"], transitions: [ { from: "ERSTELLT", to: "EINGEREICHT", action: "einreichen", requiredRole: ["FALLMANAGER"] }, { from: "EINGEREICHT", to: "GEPRUEFT", action: "pruefen", requiredRole: ["BUCHHALTER"] }, { from: "EINGEREICHT", to: "ABGELEHNT", action: "ablehnen", requiredRole: ["BUCHHALTER"], requiredFields: ["ablehnungsgrund"] }, { from: "GEPRUEFT", to: "GENEHMIGT", action: "genehmigen", requiredRole: ["TEAMLEITUNG"] }, { from: "GEPRUEFT", to: "ABGELEHNT", action: "ablehnen", requiredRole: ["TEAMLEITUNG"], requiredFields: ["ablehnungsgrund"] }, { from: "GENEHMIGT", to: "EXPORTIERT", action: "exportieren", requiredRole: ["BUCHHALTER"] }, { from: "ABGELEHNT", to: "ERSTELLT", action: "ueberarbeiten", requiredRole: ["FALLMANAGER"] }, ] };

GET /api/v1/klienten — Liste (paginiert, filterbar) GET /api/v1/klienten/:id — Einzelner Klient (360°-Daten) POST /api/v1/klienten — Klient anlegen PUT /api/v1/klienten/:id — Klient aktualisieren DELETE /api/v1/klienten/:id — Klient archivieren (Soft-Delete) GET /api/v1/klienten/:id/intakes — Intakes eines Klienten GET /api/v1/klienten/:id/einsaetze — Einsätze eines Klienten GET /api/v1/klienten/:id/abrechnungen — Abrechnungen eines Klienten GET /api/v1/klienten/:id/berichte — Berichte eines Klienten

12.2 Intake

GET /api/v1/intakes — Liste aller Intakes POST /api/v1/intakes — Neuen Intake starten PUT /api/v1/intakes/:id — Intake aktualisieren POST /api/v1/intakes/:id/abschliessen — Intake abschliessen

12.3 Einsatzplanung

GET /api/v1/einsatzplaene — Alle Einsätze (Kalender-Daten) POST /api/v1/einsatzplaene — Neuen Einsatz planen PUT /api/v1/einsatzplaene/:id — Einsatz aktualisieren POST /api/v1/einsatzplaene/:id/aktivieren — Status → AKTIV POST /api/v1/einsatzplaene/:id/beenden — Status → BEENDET

12.4 Arbeitsplätze & Berufsbilder

GET /api/v1/arbeitsplaetze — Alle Arbeitsplätze (+ Kapazität) POST /api/v1/arbeitsplaetze — Arbeitsplatz anlegen PUT /api/v1/arbeitsplaetze/:id — Arbeitsplatz bearbeiten GET /api/v1/berufsbilder — Alle Berufsbilder POST /api/v1/berufsbilder — Berufsbild anlegen

12.5 Abrechnung (mit Workflow)

GET /api/v1/abrechnungen — Liste (filterbar nach Status) POST /api/v1/abrechnungen — Neue Abrechnung erstellen POST /api/v1/abrechnungen/:id/einreichen — Workflow: einreichen POST /api/v1/abrechnungen/:id/pruefen — Workflow: prüfen POST /api/v1/abrechnungen/:id/genehmigen — Workflow: genehmigen POST /api/v1/abrechnungen/:id/ablehnen — Workflow: ablehnen (+ Grund) POST /api/v1/abrechnungen/:id/exportieren — Workflow: DATEV-Export POST /api/v1/abrechnungen/:id/stornieren — Stornierung mit Audit

12.6 Berichte

GET /api/v1/berichte — Alle Berichte POST /api/v1/berichte — Bericht aus Template erstellen GET /api/v1/berichte/:id/pdf — PDF-Download GET /api/v1/berichte/:id/docx — DOCX-Download GET /api/v1/bericht-templates — Verfügbare Templates POST /api/v1/bericht-templates — Template hochladen (Admin)
